# 随心而行 Creative Case Study 设计说明

## 目标

将「随心而行」从通用项目摘要升级为独立的 Creative Case Study 长页。它要清楚讲述：一个最初验证手势抽牌的实验，如何演进为用占问、分层解读、牌义学习与手札记录帮助用户自我探索的互动产品。

本次只改变 `follow-heart` 的项目详情页；其他项目详情页、项目星图和桌面窗口保持现状。

## 选定方案

在现有项目详情入口内，为 `follow-heart` 渲染独立组件。该组件使用新建的项目数据与样式，不抽象成通用案例引擎，避免再次把不同项目套进同一套叙事和截图结构。

## 章节与视觉节奏

1. Hero：深紫黑背景，使用生成的紫色塔罗星球海报。真实文本由 HTML 渲染；主视觉做不超过 12px 的鼠标视差。
2. Why / Context：深色档案区。左侧标题固定，右侧依次叠放「问题输入、手势切牌、结果解读」的真实截图。
3. Problem & Goal：月光白纸张区。展示五个体验问题、五个产品目标，以及可拖动的 Before / After 对比。
4. Solution Structure：深色轨道结构。中心为「此刻的问题」，六个模块沿轨道分布；点击节点更新右侧说明与界面预览。
5. Key Experience：Sticky Mockup。右侧文字滚动时，左侧依次切换问题输入、开放式问法、切牌、捏合抽牌、分层结果与牌面热点。
6. UI Showcase：GSAP ScrollTrigger 驱动的横向展厅。使用七张真实界面：问题输入、开放式问法、手势切牌、捏合抽牌、此刻解读、牌面热点、小六壬日历。
7. Design Notes / Iterations：三张不规则纸质手札，讲述手势塔罗、结果页重构、把学习嵌入占问的迭代。
8. Reflection / Next：回到深色结尾，呈现成果、反思、下一步与上/下项目导航。

## 素材映射

| 用途 | 素材 |
| --- | --- |
| Hero | 生成海报：紫色星球、三张塔罗牌、捏合手势、轨道与 UI 档案层 |
| 问题输入 | 用户提供的「你想问什么？」页面 |
| 开放式问法 | 用户提供的「AI 帮你改成更开放的问法」页面 |
| 手势切牌 | 用户提供的摄像头识别与「左右挥手切牌」页面 |
| 捏合抽牌 | 用户提供的「捏指食指捏合」抽牌页面 |
| 此刻解读 | 用户提供的宝剑三结果页 |
| 看懂牌面 | 用户提供的宝剑三热点解释页 |
| 传统文化延展 | 用户提供的小六壬起课 / 翻黄历页面 |

不使用带取色器浮窗的塔罗结果页。带蓝色遮挡的抽牌截图只作为流程状态图片，不承载需要阅读的文本。

## 文案边界

采用用户提供的 01–08 章节文案。核心原则：AI 是陪读员，不是神谕；手势是体验亮点，但触控、鼠标与辅助按钮是完整体验的一部分；小六壬只作为传统文化延展，不和塔罗主链路混写。

## 交互边界

- 章节导航、阅读进度、返回项目宇宙可用。
- Hero 视差、Why 叠页、轨道节点、Sticky Mockup、横向展厅与截图 Lightbox 可用。
- 不伪造视频或 GIF；本版全部使用真实静态界面。
- 遵循 `prefers-reduced-motion`，关闭或显著减弱滚动与视差动画。

## 技术边界

- React + TypeScript，沿用 Framer Motion。
- `UI Showcase` 使用现有的 GSAP 与 ScrollTrigger。
- 新增独立案例组件、数据模块和局部样式；`App.tsx` 只增加明确的 `follow-heart` 分支。
- 每个新增素材以独立文件保存，不覆盖已有项目海报或截图。

## 验收

- 打开「随心而行」时进入完整 8 章案例页，其他项目保持原页。
- 每个截图与其旁的功能说明能一一对应。
- Hero 不是普通网页截图，UI Showcase 图片足够大且可读。
- 桌面和移动端均可完整阅读，无重叠、破图或横向溢出。
